Docker 拉取镜像太慢怎么办：镜像加速与代理设置的思路

领域：开发运维编者：鲲鹏加速使用手记返回瀚海云枢

一、先分清是什么问题

拉取极慢但能完成，多半是网络路径问题；直接超时或失败，则可能是源站不可达。判断清楚，再决定用哪种办法。

二、使用镜像加速地址

在 Docker 的守护进程配置里添加 registry-mirrors，让它优先从可用的镜像站拉取。镜像站的可用性会变化，需要定期检查。

三、给守护进程设置代理

在 systemd 的 docker 服务下添加 drop-in 配置，设置 HTTP_PROXY、HTTPS_PROXY 和 NO_PROXY，然后重新加载并重启服务。内网地址要放进 NO_PROXY。

四、构建过程中的代理

构建镜像时可以通过构建参数传入代理，但注意不要把代理地址写进最终镜像里，避免泄露。

五、其他仓库

gcr.io、quay.io 等仓库同样适用上述思路。Kubernetes 节点则需要在容器运行时（如 containerd）里单独配置。

小结

镜像加速和代理是互补的。先用镜像站解决常用镜像，再用代理兜底，能显著缩短拉取时间。
